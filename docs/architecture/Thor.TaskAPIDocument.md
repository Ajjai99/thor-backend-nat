# Thor.TaskAPI

Note: This is a living document. This document should be updated based on the decisions made while implementing the TaskAPI or related service.


## 1. Overview

TaskAPI is the multi-tenant orchestration layer for the Connectors. Connectors communicate with TaskAPI to poll for tasks and generate S3 presigned URL for file uploads to S3. The frontend application creates the configurations for scanning datasources.
TaskAPI supports API versioning. This should be considered in all decision making

## 2. Application flow

The user creates the Scan configuration from the frontend. The configuration contains the list of datasources (targets) to scan along with Connector settings.

Scan tasks are created using the scan configuration. This is done by the scheduler or mannually by an endpoint exposed in the TaskAPI.

The Connectors fetch the active tasks from the TaskAPI endpoint. When the task is consumed by the connectors, the status of the tasks should be changed to in-progress, so that multiple connectors dont work on the same task. If a task is not updated for a given amount of time, then the task status is resetted and is available for connectors to work on.

Connectors can update the status of a task. TaskAPI should manage that a single task should not be processed by multiple connectors.

## 3. Authentication

The requests to the TaskAPI are already validated by the custom lambda authorizer. The lambda authorizer will add the tenant-id in the header, which can be used to create connection to the right database.

Two types of users can access the TaskAPI:
- The Connectors uses the API key issued by the TaskAPI to generate a JWT.
- The application users who uses the JWT issued by the IDP.

User acessing an endpoint should be confirmed before implementation. 

## 4. Database and tables

Tables that are related to API keys, authentication methods, connector configuration are present in the master table.
Tables that store scan configurations, scan sessions, scan tasks, Datasources are all present in respective tenant tables.
Use appropriate database connections based on which table data is being accessed.
